# DocsWatcher CLI

```
docswatcher scan <path> [--repo owner/name] [--ref ..] [--sha ..] [--knowledge <dir>] [--write-expected]
docswatcher match <path> [--format json|text] [--report <file>] [--inventory <file>] [--include-low] [--today YYYY-MM-DD] [--knowledge <dir>]
docswatcher validate [<dir>] [--today YYYY-MM-DD]
```

Exit codes: `scan` 0. `match` 1 when any breaking finding is open, else 0. `validate` 1 on any error.

Knowledge resolution: `--knowledge <dir>`, else `./knowledge` if it exists, else the copy bundled in the jar.

## Run from the jar

```
source build-env.sh
./mvnw -q -pl cli -am -DskipTests package
java --enable-native-access=ALL-UNNAMED -jar cli/target/docswatcher-cli.jar match . --format text
```

The `--enable-native-access` flag silences the JDK warning about the tree-sitter binding loading a native library.

## Native image

The `native` profile builds `cli/target/docswatcher` with GraalVM native-image:

```
./mvnw -Pnative -pl cli -am -DskipTests package
```

Native-image needs JNI and resource configuration for the tree-sitter binding. Configuration generated by the tracing agent lives in `src/main/resources/META-INF/native-image/dev.docswatcher/cli/`. To regenerate it, run the fat jar over the fixtures with the agent:

```
java -agentlib:native-image-agent=config-output-dir=cli/src/main/resources/META-INF/native-image/dev.docswatcher/cli \
  -jar cli/target/docswatcher-cli.jar scan knowledge/fixtures/stripe-java-sources/repo --knowledge knowledge
```

See the status section at the bottom of this file for the current state of the native build.

## Native build status (2026-09-18)

Builds and runs on Linux x64 with GraalVM Community 25.0.0. `cli/target/docswatcher` is about 46 MB and runs `scan`, `match`, and `validate` against the fixtures.

The release workflow also builds it on macOS arm64 and Windows x64 runners (`cli/target/docswatcher.exe` there). The `macos` and `windows` profiles switch on by OS and include only that platform's tree-sitter libraries in the image. There is no macOS x64 build: GraalVM Community stopped publishing macOS x64 after JDK 25.0.1.

Two things were needed:

1. **Reachability metadata repository disabled** in the `native` profile. native-maven-plugin 1.1.14 ships a metadata schema newer than GraalVM 25.0.0 understands and refuses to build. Our own JNI and resource configuration from the tracing agent is enough.
2. **zlib development link.** The linker needs `libz.so`, which comes from the `zlib1g-dev` package on Debian and Ubuntu. If you cannot install it, create the link locally and the profile picks it up from `cli/native-link/`:

   ```
   mkdir -p cli/native-link && ln -sf /usr/lib/x86_64-linux-gnu/libz.so.1 cli/native-link/libz.so
   ```

   The link is ignored by git.

The tree-sitter binding still extracts its shared library to a temp directory at startup and prints the JDK native-access warning; startup is under two seconds. Bundling the grammars statically is future work.
