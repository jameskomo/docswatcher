The Google Maps JavaScript API changelog documents updates, bug fixes, deprecations, and new features across various API versions.
Key changes include enhanced accessibility, performance improvements, visual updates, and advanced features like Advanced Markers and data-driven styling.
Support for older technologies like Internet Explorer 11 has been dropped in favor of newer technologies like WebGL 2.0.
Updates focus on improved developer experience, user accessibility, and platform stability through bug fixes and feature enhancements.
Users should consult the changelog and documentation for detailed information about specific changes and their impact.

The Maps JavaScript API team regularly updates the API with new
features, bug fixes, and performance improvements. You can indicate which
version of the API to load within your application by specifying it in the
v parameter of the Maps JavaScript API bootstrap
request. Read more about
versioning .
This changelog lists releases by date and version number, along with
associated changes.
To receive updates on new Maps API versions, please subscribe to the
google-maps-js-api-v3-notify group.
As of August 26, 2021 starting with the beta channel, Maps JavaScript API
may make additional calls to report telemetry information for the purpose of calculating the SLO
(Service Level Objective) of several features. You may need to update your Content Security Policy
to ensure these calls are not blocked at browser-level. For more information, please see the
FAQ .

3.64.12d

3.64.8b
8 April, 2026
Changes:
[alpha channel] Route3DElement, Marker3DElement and Polyline3DElement with autofitsCamera will not cause camera updates when removed from the DOM. For Route3DElement, errors or empty responses have no effect on the camera. Also, changing autofitsCamera from true to false on a given element will not update the camera to exclude that element, but it will opt the element out of future camera updates.
The zIndex of an AdvancedMarkerElement is now determined by its explicitly set value or, by default, by its vertical pixel position. Explicit values take precedence over the default. To avoid markers lower on the screen without a zIndex unexpectedly overlap those with one, we recommend applying zIndex consistently across all markers.
TypeScript declarations now include an interface mapping HTML tag names to JS classes ( google.maps.HTMLElementTagNameMap and the global HTMLElementTagNameMap ), an interface mapping HTML tag names to each JS class's EventMap ( google.maps.HTMLElementEventMapTagNameMap ), an interface of all custom CSS properties ( google.maps.CSSProperties ), and each string-based enum has a string union type defined (as ${EnumName}String ) and that string union is used for that enum throughout the declarations. addEventListener() is also overloaded on each custom element with its EventMap types, and google.maps.importLibrary() is overloaded to correctly type each returned library for the passed in library name.

15 November 2016
Version 3.27 of the Maps JavaScript API is now available as the
experimental version. (See the guide to
API versioning .)
Changes:
A new gestureHandling option in the MapOptions
object helps you optimise your users' experience when interacting with the
map on mobile devices. The available values are:
greedy : The map always pans (up or down, left or
right) when the user swipes (drags on) the screen. In other words, both a
one-finger swipe and a two-finger swipe cause the map to pan.
cooperative : The user must swipe with one finger to scroll
the page and two fingers to pan the map. If the user swipes the map with one
finger, an overlay appears on the map, with a prompt telling the user to use
two fingers to move the map. View the sample above on a
mobile device to see cooperative mode in action.
none : The map is not pannable or pinchable.
auto (default): The behavior is either
cooperative or greedy , depending on whether the
page is scrollable or not.
For more details and examples, see the
developer's guide .
The fullscreen control is visible by default on mobile devices, so users
can easily enlarge the map. When the map is in fullscreen mode, users can
pan the map using one or two fingers. Note: iOS doesn't
support the fullscreen feature. The fullscreen control is therefore not
visible on iOS devices.

Change in via waypoints in Directions service response
29 August 2016
The
via_waypoints
field in the Directions service response contains an array of waypoints that
were not specified in the original request. The via_waypoints
field will continue to appear in the draggable directions response, but is
deprecated in the alternative route response . Version 3.27
will be the last version of the API that supports via_waypoints
in alternative routes.
The recommended approach is to request alternative routes, then display
all routes as non-draggable plus the main route as draggable. Users can drag
the main route until it matches an alternative route. The
via_waypoints field is available on the resulting route (dragged
by the user).
