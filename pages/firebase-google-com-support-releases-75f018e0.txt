Firebase AI Logic
Firebase AI Logic supports the latest Gemini stable
model gemini-4-neon . You can
directly access this model in your mobile or web app
via either the Gemini Developer API or the
Agent Platform Gemini API (formerly Vertex AI) .
Billing : Accessing gemini-4-neon requires the
pay-as-you-go Blaze pricing plan regardless of your Gemini API provider.
Short-term availability : For the Agent Platform Gemini API (formerly Vertex AI) ,
gemini-4-neon is a
short-term availability model .
To avoid service disruptions when models are updated, we strongly recommend
using
Firebase Remote Config
or
server prompt templates
to dynamically manage the model name in your app.
If you're migrating from previous models, note the following for this new
model:
Thinking levels ( HIGH default, no XHIGH or thinkingBudget ) :
Supported
thinking levels
in Firebase AI Logic are LOW , MEDIUM , and HIGH (default).
Note that Firebase AI Logic does not currently support
XHIGH .
Does not support setting thinking level of MINIMAL (the
request will fail with a 400 error).
Does not support using thinkingBudget (there's no
backwards-compatibility; the request will fail with a 400
error).
Context caching :
Supports
implicit caching
by default (with a minimum of 4,096 input tokens on the
Gemini Developer API and 6,144 input tokens on the
Agent Platform Gemini API (formerly Vertex AI) ).
Does not support explicit caching.
Token limits & unsupported parameters :
Input token limit is 1,048,576 tokens, and single-segment output
token limit is 65,536 tokens for both streaming and non-streaming
requests. Firebase AI Logic does not yet support the "long
decode" capability.
Sampling parameters ( temperature , topP , topK ) are ignored, and
frequencyPenalty , presencePenalty , and candidateCount fail
with a 400 error.
Additional document input types :
In addition to PDFs and plain text, gemini-4-neon (along with
other Gemini 4.x models) supports
Microsoft Office and OpenDocument files
( .doc , .docx , .dotx , .ppt , .pptx , .xls , .xlsx , .odt ,
.odp , .ods ).

Firebase AI Logic
Firebase AI Logic supports the latest stable
Gemini TTS models ( gemini-3.8-flash-tts and
gemini-3.8-flash-lite-tts ) for
text-to-speech (TTS) generation via either
the Gemini Developer API or the Agent Platform Gemini API (formerly Vertex AI) .
Vocal direction and multi-speaker dialogue : Guide vocal delivery using
turn-level SpeechMetadata ( style and speaker on TextPart ),
inline angle-bracket vocal tags
( <...> ), and
pipe backchannels
( |...| ) for two-speaker conversations.
Voices and languages : Choose from
30 core prebuilt voices ,
over 2,000 preset voices from the
Extended Voice Library ,
or custom voices created
with Voice design and Voice replication. The models automatically detect the
language of the input text across
over 100 languages .
Audio output formats : Unary requests ( generateContent ) return a
complete WAV file ( audio/wav ), while streaming requests
( generateContentStream ) return headerless raw 16-bit PCM chunks
( audio/l16 ).
Migration from gemini-3.1-flash-tts-preview : The preview model
gemini-3.1-flash-tts-preview will shut down on November 17, 2026 . If
your app uses this legacy model, see the
migration guide
to update your model name, prompt format, and audio handling before that
date.

November 02, 2026
Gemini API
For the Gemini Developer API (Google AI), starting
December 1, 2026 , requests to the Gemini 2.5 Pro and Flash models
will be automatically routed to newer Gemini 3.x models:
Gemini 2.5 Pro ( gemini-2.5-pro ): Requests will be automatically
routed to gemini-3.8-flash .
Gemini 2.5 Flash ( gemini-2.5-flash ): Requests will be
automatically routed to gemini-3.5-flash-lite .
Gemini 2.5 Flash‑Lite ( gemini-2.5-flash-lite ): No changes at this
time.
Note that for the Agent Platform Gemini API (formerly Vertex AI) , gemini-2.5-pro ,
gemini-2.5-flash , and gemini-2.5-flash-lite were already shut down
(retired) on October 20, 2026.
Breaking changes and behavioral differences when requests are routed to
Gemini 3.x models:
Billing : Inference will be billed at the rates of the newer models.
Unsupported parameters : Both gemini-3.8-flash and
gemini-3.5-flash-lite
do not support several sampling parameters :
Frequency penalty, presence penalty, and candidate count (for
gemini-2.5-pro routed to gemini-3.8-flash ): gemini-3.8-flash does
not support frequencyPenalty , presencePenalty , or
candidateCount . Requests that include these parameters will fail
with a 400 error.
Temperature, top-K, and top-P : All general-use Gemini 3.x
models ignore temperature , topK , and topP . For more deterministic
responses, define system instructions with explicit rules for your
specific use case.
Prefilled model turn validation : Prefilling model turns is no longer
supported in Gemini 3.x models. If the last non-empty turn in the
request is a model turn, the request will fail with a 400 error.
Thinking configuration :
No support for MINIMAL thinking level on gemini-3.8-flash : If
you set the
thinking level
to MINIMAL for a request routed to gemini-3.8-flash , the request
will fail with a 400 error.
Use thinking levels instead of thinking budgets : Thinking
budgets are supported by Gemini 3.x models for
backwards-compatibility, but they are strongly discouraged (especially
starting with gemini-3.8-flash ). We recommend migrating from
thinkingBudget to
thinkingLevel .
If you still use Gemini 2.5 models with Firebase AI Logic , we
strongly recommend explicitly updating your app to use a newer model (like
gemini-4-argon , gemini-3.8-flash , or gemini-3.5-flash-lite ) and testing
your model configuration before December 1, 2026 . For more details, see the
deprecated and shutdown models FAQ .

Firebase AI Logic
To reflect the renaming of Vertex AI to Gemini Enterprise Agent
Platform (or "Agent Platform"), the legacy "Vertex AI" initialization syntax
(such as vertexAI or VertexAIBackend ) has been removed from the
Firebase AI Logic SDKs in favor of the new "Agent Platform"
initialization syntax (such as agentPlatform or AgentPlatformBackend ).
The only difference for the new "Agent Platform" initialization syntax is
the default
location for accessing the model .
The default location for the "Agent Platform" syntax is global ,
whereas the default location for the legacy "Vertex AI" syntax was
us-central1 . Note that most new Gemini models do not
support us-central1 .
If you want to use us-central1 (or another location) with the new
syntax, you can explicitly specify the location when initializing the
backend service.
If you use the Agent Platform Gemini API (formerly Vertex AI) , then you must update your
apps to use the new "Agent Platform" initialization syntax if you upgrade
to the latest versions of the SDKs . For platform-specific code examples
and full details, see the
FAQ describing the required changes .

Cloud Storage for Firebase
To continue using and accessing Cloud Storage for Firebase , your
Firebase project must be on the Blaze pricing plan. These changes
were first announced back in September 2024.
What will happen: If you have an *.appspot.com default bucket and your
Firebase project is still on the Spark pricing plan , then you'll
lose console access to your bucket and your API calls will start returning
402 and 403 errors.
What you need to do: To regain access and quality of service, upgrade to
the pay-as-you-go Blaze pricing plan . No-cost usage is still available even on the
Blaze pricing plan.
Learn more about these changes in our
FAQs about changes to Cloud Storage for Firebase pricing and default buckets .

November 10, 2025
Cloud Functions
Version 7.0.0 of the Firebase SDK for Cloud Functions contains breaking changes as well as
new features and enhancements.
This release drops support for Node.js 16, requires TypeScript v5, and removes
the deprecated functions.config() API.
Review these release notes carefully to avoid issues or outages.
Breaking changes
Minimum Node.js version is now 18. As of v7.0.0, the SDK requires
a Node.js runtime of version 18 or newer. Support for Node.js 14 and 16 has
been removed.
Impact: Functions using this SDK version fail to deploy or run on
Node.js runtimes older than v18.
Action Required: Before upgrading the SDK, you must set the Node.js
version
to update your function's runtime environment to Node.js 18 or higher.
We recommend using the latest Node.js LTS version supported by Cloud
Functions.
The functions.config() API has been removed. Following the
deprecation schedule announced in v6.0.0, runtime configuration with
functions.config() has been removed entirely.
Impact: Calling this API now throws a runtime error and causes build
time errors if you are using TypeScript. Any function relying on
functions.config() fails at runtime.
Action Required: You must migrate from runtime
configuration
to environment variables using the params module.
TypeScript v5 is now required. The SDK has been upgraded from
TypeScript v4.3 to v5.9 and now targets ES2022.
Impact: This may introduce new type-checking errors in your project if
you are using an older version of TypeScript or if your code relies on
older type definitions.
Action Required: Update your project's TypeScript version to v5.x and
resolve any resulting type errors.
The Event interface, which defines the wire format for an
event, has been changed to LegacyEvent . This change mitigates an
api-extractor conflict caused by an open issue with Rushstack
( #3581 ).
Impact: Very few users are likely to be affected, as this type
represents the internal state of function triggers.
Action: If you rely on this type, update your code to use
LegacyEvent instead.
Improved error handling for async handlers in the Emulator. We
have improved how unhandled errors are processed in the Local Emulator
Suite. Previously, an unhandled error or rejected Promise in an async
onRequest handler would cause the request to hang until a platform timeout.
Impact: As of v7.0.0, these unhandled errors now correctly and
immediately return a 500 Internal Server Error.
Action Required: This is a technical breaking change, as it changes
error handling behavior. This provides faster, more accurate error
feedback during local development. Ensure your error handling logic is
correct and not reliant on the old timeout behavior.
The SDK is now published as both CommonJS (CJS) and ECMAScript
Modules (ESM). This provides first-class support for modern bundlers (like
Vite and esbuild) and native import syntax, which can lead to optimized
function sources and smaller bundle sizes. The package.json exports map
now properly resolves for both require and import .
This release adds a new function trigger for Firebase Data
Connect (FDC), onMutationExecuted() . This allows you to execute functions
in response to data mutations.

All newly provisioned Cloud Storage for Firebase default buckets
will have the name format of PROJECT_ID .firebasestorage.app (instead
of PROJECT_ID .appspot.com ). These buckets will follow
Google Cloud Storage pricing and usage
which provides an "Always Free" tier for buckets in
US-CENTRAL1 , US-EAST1 , and US-WEST1 .
All existing *.appspot.com default
buckets will experience no changes right now. However, note that by
February 03, 2026 , all Firebase projects must
be on the pay-as-you-go Blaze pricing plan to continue using Cloud Storage for Firebase .

projects.defaultBucket.create
now provisions default buckets with the name format of
PROJECT_ID .firebasestorage.app . Also, using this API now requires the
pay-as-you-go Blaze pricing plan .

now decommissioned and will return 404 errors:

resource in a project.

Vertex AI in Firebase
Vertex AI in Firebase is now Generally Available (GA) and can be
used in production apps.
Use the Firebase AI Logic client SDKs to call the
Agent Platform Gemini API (formerly Vertex AI) directly from your app. They're available for
Swift ,
Android ,
Web ,
and
Flutter .
These client libraries are built specifically for use with mobile and web
apps, and they offer important integrations with other Firebase services:
Firebase App Check : Help secure the
Gemini API against unauthorized clients.
Firebase Remote Config :
Dynamically and conditionally control your prompts, as well as model names,
versions, and configurations — all without releasing a new version of your
app.
Cloud Storage for Firebase : Send
large image, video, audio, and PDF files in your multimodal requests.
If you used the preview version of the library, visit the
migration guide to learn about some
important updates.

September 09, 2024
Cloud Functions
Version v6.0.0 of the
Firebase SDK for Cloud Functions contains breaking changes that may affect some apps. Review
these release notes carefully to avoid issues or outages.
Additionally, v6.0.0 introduces new features and bug fixes, and starts a
one-year deprecation clock for runtime environment configuration with
functions.config .
Breaking: Cloud Functions for Firebase now defaults to 2nd gen.
Previously, functions that do not explicitly specify a version when importing
the SDK were interpreted as 1st gen. As of v6.0.0, such functions are
interpreted as 2nd gen, and if they are written using 1st gen syntax they are
likely to fail to deploy.
To work around potential deployment issues, make sure that all 1st gen
functions explicitly import the
version-specific subpackage firebase-functions/v1 .
However, the recommended solution for all 1st gen functions is to upgrade to
2nd gen as described in
Upgrade 1st gen Node.js functions to 2nd gen . 2nd gen functions are based on Cloud Run functions, providing
better performance, better configuration, better monitoring, and more.
Runtime environment configuration with
functions.config is deprecated as of September 5, 2024, and will no
longer be supported after the next major version of Cloud Functions .
You are strongly recommended to
migrate to environment variables .
Thanks to enhancements released just prior to v6, the
Local Emulator Suite now supports emulation of
Firebase alert triggers and task queue functions.
See specific guidance on how to
interact with Firebase alerts
and how to
instrument your app for task queue functions emulation .

Cloud Messaging
For apps using Android Q+ and Google Play
services version 19054000 and later,
some notifications sent through the HTTP v1 API now are subject to delegation
by Google Play services. This means that high-priority notifications that meet
certain criteria are displayed by Google Play services on behalf of the app,
without any need to start the app.
Note that this feature is currently in Beta, and is subject to change. You can
opt out of the Beta program, but we strongly recommend leaving delegation
enabled for its benefits to device battery and memory. See
Notification delegation with Google Play services
to learn about how to opt out, how delegation affects reporting, and more.
